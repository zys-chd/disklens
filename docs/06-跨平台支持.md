# 跨平台支持与验证矩阵

> 更新：2026-11-10 ｜ 本文只记录**实测结论**，不写"理论上支持"。

## 1. 验证矩阵

| 平台 | 编译 | 核心测试 | 真机运行 | 制品 | 状态 |
|---|---|---|---|---|---|
| Linux x86_64 (Arch, kernel 7.2) | ✅ | ✅ 87/87 | ✅ 窗口 + 扫 ~/Projects / ~ 实测 | `.deb` / `.AppImage` | **可用（主平台）** |
| Windows 10/11 x64 | ✅ | ✅ 87/87（GitHub windows-latest runner 真跑） | 无环境（未跑） | `.msi` / `.exe` | 测试全绿；窗口交互未实测 |
| macOS 12+ (x86_64 / arm64) | ✅ 交叉 `cargo check --tests` 零错误 | ⚠️ 未在 runner 上跑 | 无环境（未跑） | `.dmg` / `.app` | 代码可编译；测试待 `ENABLE_MACOS_CI` 开启 |

> 上表的 "87/87" 是 CI 上真实执行的 `cargo test -p disklens-core` 结果（Linux 与 Windows 各跑一遍）。

CI 流水线（`.github/workflows/ci.yml`）：
- `test` 矩阵：**ubuntu-22.04 / windows-latest / macos-14 三平台真跑 `cargo test -p disklens-core` + `tsc` + `vitest`**（不是只编译）
- `build` 矩阵：仅在打 tag（`v*`）或手动 `workflow_dispatch` 时跑，产出安装包并上传 artifact（保留 30 天）
- macOS runner 计费 10×，所以构建矩阵刻意不跟每次 push 跑
- **macOS 任务默认关闭**（`vars.ENABLE_MACOS_CI != 'true'` 时跳过）：实测本账号分配不到 macOS runner——一个只跑 `uname -a` 的探针 job 也在 1 秒内被取消、0 步，属计费/额度限制。开启方式：仓库 Settings → Secrets and variables → Actions → Variables → `ENABLE_MACOS_CI = true`
- 关闭期间 macOS 的正确性由本地交叉检查保证：`~/.cargo/bin/cargo check -p disklens-core --tests --target aarch64-apple-darwin`（零错误）

## 2. 已发现并修复的跨平台缺陷（真实 bug，非推测）

| # | 缺陷 | 影响 | 修法 |
|---|---|---|---|
| 1 | 安全分级规则用 `/` 写，Windows 路径是 `\`，`globset` 匹配失败（实测：`*/node_modules` vs `C:\...\node_modules` → false） | **Windows 上整套安全分级静默失效**，删除护栏的依据全丢 | 匹配前两边统一归一化为 `/`；Windows/macOS 比较不区分大小写 |
| 2 | 硬链接去重使用 `MetadataExt::file_index()` / `volume_serial_number()` | 这俩是 **unstable feature `windows_by_handle`**，Windows 直接编译失败（CI 抓到 E0658） | Windows 退化为不去重并在统计里标记；Unix/macOS 保持 `(dev, ino)` 精确去重 |
| 3 | `exclude` 用 `Path::starts_with` 直接比路径 | 调用方给的是短名（`RUNNER~1`）或带 `./`/尾斜杠的同一路径时，与 canonicalize 后的扫描根对不上 → **排除静默失效**，被排除的目录照样被统计进去 | 预先把 exclude 规范化成 `/` 分隔字符串再比前缀；加了回归测试 |
| 4 | 测试自身假设了 unix 路径语义（`/home/u/...`、`/usr`、`/var`、`Path::new("/")`） | Linux 绿、Windows 一片红：Windows 上 `/x` 是**盘符相对路径**，会被归一化成带 cwd 前缀 | 测试夹具改为按平台给真实绝对路径（`home()` 在 Windows 返回 `C:\Users\u`）；unix 专属规则用例 `#[cfg(unix)]` 门控，Windows 等价项用 `C:\Windows` 形状单独测 |

第 2 条的代价要写明：**Windows 上 pnpm store、WinSxS 等硬链接场景会把空间算高**（同一份数据按链接数重复计）。UI 与 README 已提示。

## 3. 各平台实现差异（代码位置）

| 能力 | Linux | Windows | macOS | 代码 |
|---|---|---|---|---|
| 打开文件（默认程序） | `xdg-open` | `start` / ShellExecute | `open` | `src-tauri/src/open.rs` |
| 在文件管理器中定位 | dbus `FileManager1.ShowItems`，失败回退 `xdg-open` 父目录 | `explorer /select,<path>` | `open -R <path>` | 同上（argv 构造已抽纯函数，可在 Linux 上单测断言） |
| 移到回收站 | freedesktop Trash 规范（gio） | `SHFileOperation` | `NSFileManager trashItem` | `trash` crate，core 的 `ops.rs` 统一调用 |
| 盘符/卷列表 | `/proc/mounts` 经 sysinfo | 盘符 `C:` / `D:` | `/` + `/Volumes/*` | sysinfo `Disks` |
| 硬链接去重 | `(st_dev, st_ino)` | **不去重**（见 §2） | `(st_dev, st_ino)` | `crates/disklens-core/src/scan.rs` |
| 跨文件系统边界 | `st_dev` | 卷序列号（不可得 → 由挂载点判断） | `st_dev` | 同上 |
| 大小写敏感 | 敏感 | 不敏感 | 不敏感（默认 APFS） | `rules.rs` / `guard.rs` |
| 配置/快照目录 | `~/.config/disklens`、`~/.local/share/disklens` | `%APPDATA%\disklens` | `~/Library/Application Support/disklens` | `dirs` crate |

## 4. 本地交叉编译检查（每次改 core 必跑）

在 Linux 上不装虚拟机也能抓 Windows/macOS 的编译错误：

```bash
# 本机 rustup 装在 ~/.cargo/bin（未改 PATH）；系统 /usr/bin/cargo 是 Arch 的，没有交叉 target
~/.cargo/bin/rustup target add x86_64-pc-windows-msvc x86_64-apple-darwin aarch64-apple-darwin
~/.cargo/bin/cargo check -p disklens-core --tests --target x86_64-pc-windows-msvc
~/.cargo/bin/cargo check -p disklens-core --tests --target x86_64-apple-darwin
~/.cargo/bin/cargo check -p disklens-core --tests --target aarch64-apple-darwin
```

> 用系统 `cargo` 跑会得到一串 `can't find crate for core`（sysroot 里没有该 target 的 std），别误判成代码错误。

> 这条流程是在 CI 抓到 `windows_by_handle` 之后补上的——它本该在提交前就发现。

图标资产：Windows 打包必须有 `src-tauri/icons/icon.ico`、macOS 需要 `icon.icns`。用 `./app/node_modules/.bin/tauri icon src-tauri/icons/icon.png` 一次生成全套（源图 ≥512×512）。

## 5. 仍未覆盖（明确列出，避免"以为验过"）

1. **Windows / macOS 真机运行**：本机无环境，只有 CI 的编译 + 测试，没有真实窗口交互。
2. **Windows 回收站**：`trash` crate 的行为未在 Windows 上实测。
3. **macOS 未签名包**：首次打开需 `xattr -dr com.apple.quarantine /Applications/DiskLens.app`；Gatekeeper 仍可能提示。
4. **路径长度**：Windows `MAX_PATH` 限制、`\\?\` 前缀处理只做了归一化，未在长路径场景实测。
5. **非 UTF-8 文件名（Windows UTF-16 代理对）**：显示用 lossy，文件操作对这类路径的行为未实测。
6. **多显示器/缩放**：WebView 在高 DPI 下的字体渲染未验。

## 6. 验收口径（多平台）

- 编译 + 测试：三平台 CI 全绿为准（`test` 矩阵）
- 制品：打 tag 后 CI 产出四个包，能装、能开、能扫（Linux 本机已验证，另两平台以 CI 产物 + 用户实机为准）
- 不承诺：签名、公证、自动更新、多语言
