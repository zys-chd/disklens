# 性能基准（实测）

> 环境：Arch Linux / kernel 7.2.14 / NVMe / rustc 1.99.1 / release 构建
> 测量人：主控复测（2026-11-09），不是子代理自报数字

## 1. 扫描性能

| 目标 | 条目数 | 逻辑大小 | 耗时 | 峰值 RSS | 与 `du --apparent-size -sB1` 误差 |
|---|---|---|---|---|---|
| `~/Projects` | 47,450 | 4.06 GB | **92 ms** | 9.1 MB | **-0.000%** |
| `~`（整个 home） | 717,672 | 48.73 GB | **1.37 s** | **97.7 MB** | **-0.002%** |

复测命令：
```bash
cd ~/Projects/disklens
cargo build --release --example scan
/usr/bin/time -v target/release/examples/scan ~          # 峰值 RSS / 墙钟
du --apparent-size -sB1 ~                                # 对照口径（逻辑大小）
```

阈值对照（04-测试计划 §4）：`~` 目标 ≤ 8s → **实际 1.37s，达标 5.8×**；峰值 RSS 目标 ≤ 350MB → **实际 97.7MB，达标 3.6×**。

## 2. 关于 `du -sB1` 的 -3.5% 差异（不是 bug）

| 口径 | `~` 数值 | 含义 |
|---|---|---|
| 本工具 / `du --apparent-size` | 48,733,011,203 / 48,733,773,027 | **逻辑大小**（`st_size` 之和） |
| `du -sB1`（默认） | 50,501,746,688 | **分配块占用**（文件系统实际占用） |

差异来源：大量小文件按 4KB 块取整（分配 > 逻辑）、以及稀疏/压缩文件反向。**验收口径 = 逻辑大小**，已同步到 PRD F2、测试计划 §4、架构 §3 的 I3。→ 结论：UI 里显示的是"文件有多大"，不是"占了多少块"，需在 UI 说明（已知项）。

## 4. 结论

核心引擎性能远超目标，且**单线程 `std::fs` 遍历已达标**（未启用 jwalk/rayon）——
按 ponytail 原则保留更简单的实现；若将来单盘条目数进入 500 万级或网络盘场景，
第一优化项是切 jwalk 并行（`scan.rs` 已隔离，替换面仅一个文件）。
