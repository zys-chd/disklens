# 测试计划

> 原则（用户明确要求）：**测试必须能复现真实 bug，不是 happy path 拼数量**。每个修过的 bug 必须补一条回归测试，且该测试在修复前必须是失败的。

## 1. 测试分层

| 层 | 工具 | 范围 | 是否阻塞交付 |
|---|---|---|---|
| L1 Rust 单元 | `cargo test -p disklens-core` | 聚合不变量、硬链接去重、跨盘、排序/分页、guard、快照 diff | 是 |
| L2 Rust 集成 | `cargo test -p disklens-core --test scan_fixture` | 真实临时目录树 vs `du -sB1` 对照 | 是 |
| L3 前端单元 | `vitest run` | `formatBytes`、`tree.flattenRows`、排序比较器、treemap 布局入参 | 是 |
| L4 前端可视化冒烟 | `vitest` + 浏览器截图（mock 后端） | 树渲染、treemap 出图、右键菜单、删除对话框 | 是 |
| L5 真机手动验收 | `cargo tauri dev` | 扫真实 /home、拖拽、三平台菜单、真删到回收站 | 是（用户） |
| L6 性能基准 | `scripts/bench.sh` | 扫描耗时/内存对比 `du` 与既有 Python 版 | 是（指标表） |

## 2. 测试夹具（fixture）设计 — 覆盖真实痛点

`crates/disklens-core/tests/fixtures/build.rs` 生成临时树：

| 场景 | 构造 | 断言 |
|---|---|---|
| 基础 | 3 层 × 3 目录，文件大小已知 | 每层 size 精确匹配；I1/I2 不变量 |
| 硬链接 | A/f1 (10KB)，B/f2 = hardlink(A/f1) | 总 size 只计 10KB 一次，不是 20KB（**Steam 场景**） |
| 符号链接 | link → ../target；linkdir → ../target | 不跟随；link 自身 size=0；不产生环 |
| 符号链接环 | a/link → b，b/link → a | 扫描正常结束，不 hang |
| 权限拒绝 | 0700 目录（非属主）/ chmod 000 | 不 panic；error_count ≥ 1；其余结果正确 |
| 非 UTF-8 文件名 | `OsStr::from_bytes(b"\xff\xfe")`（unix） | 不 panic，display 用 lossy |
| Unicode/长名 | 中文、emoji、255 字节名 | 名称与路径正确 |
| 零字节 / 稀疏文件 | 0B 文件；`set_len` 1GB 稀疏 | size 取 `metadata.len()`（稀疏文件按逻辑大小，文档说明） |
| 深路径 | 40 层嵌套 | depth 正确，不栈溢出 |
| 跨设备 | 无可移植手段 → 用 `/proc` 或 `/sys` 挂载点（unix，存在则测，不存在 skip） | `cross_filesystems=false` 时不进入 |
| 大目录分页 | 1 个目录 5000 文件 | `list_children` limit=100 分页正确、total=5000 |
| 取消 | 扫描大目录，100ms 后 cancel | 1s 内返回，`cancelled=true`，已扫节点不变量仍成立 |

夹具统一 `tempfile::TempDir`，测后自动清理。

## 3. 必测边界（写进用例名，防止漏）

- 空目录 / 只有目录没文件 / 根路径不存在 / 根路径是文件（应报错而非崩）
- 路径含空格、中文、`#`、`%`（IPC 传递）
- `list_children` 的 `offset` 超过 total（返回空，不报错）
- `sortBy=mtime` 且多个相同 mtime（排序稳定，不抖动）
- 快照 diff：A 有 B 无（删除）、B 有 A 无（新增）、大小不变、超大 delta 溢出（u64 相减用 i64 且保护）
- guard：`/`、`/usr`、`~~/`（规范化后=home）、`/home/zys/Projects`、`..` 穿越、空串、不存在路径
- `delete_permanent`：confirmText 不匹配必须拒绝；部分成功时 ok/failed 都要正确

## 4. 性能验收（M1/M4 各跑一次，记录到 docs/bench.md）

| 指标 | 阈值 | 测量方法 |
|---|---|---|
| 扫 `~/Projects` (~3.4G) | ≤ 2s 热缓存 | `hyperfine` 或 `time`，3 次取中位 |
| 扫 `~` (76G, ~100万) | ≤ 8s 热缓存 / ≤ 60s 冷 | 同上；与 `du -sx ~` 对照 |
| 结果正确性 | 与 `du --apparent-size -sB1` 误差 < 0.5%（逻辑大小口径；`du -sB1` 块占用差异约 3%，属 04 §7 预期） | 脚本 diff |
| 峰值 RSS | ≤ 350MB（100 万节点） | `/usr/bin/time -v` |
| 前端 10 万行滚动 | 无长任务 > 50ms | Chrome DevTools Performance（mock 数据） |
| Treemap 5000 矩形 | ≤ 200ms | `performance.now()` 打点，测试里断言 |

## 6. 回归规则

1. 任何 bug 修复 PR：先写一个**在旧代码上失败**的测试，再修。
2. 测试名写清场景：`hardlink_dedup_counts_once_not_twice`，不写 `test_scan_2`。
3. 不为覆盖率写测试；只测行为与不变量。
4. 弱断言禁止：`assert!(result.is_some())` 这类不算验证，必须断言具体值。

## 7. 已知不接受的情形（写进文档避免误报）

- 稀疏文件按 `st_size` 计（不按实际占用 `st_blocks`）——与 `du` 存在差异，属预期；在 UI 提示"逻辑大小"。
- `/proc`、`/sys` 内核伪文件系统大小无意义，扫描默认排除（exclude 内置）。
- APFS 克隆文件、Windows 压缩文件同理按逻辑大小。
