## 2. 核心数据模型

```rust
// crates/disklens-core/src/model.rs
pub type NodeId = u32;
pub const NO_PARENT: NodeId = u32::MAX;

#[derive(Clone, Copy, PartialEq, serde::Serialize)]
pub enum NodeKind { Dir, File, Symlink }

pub struct Node {
    pub name: Box<str>,     // 只存文件名，绝对路径按需拼（省内存）
    pub parent: NodeId,
    pub children: Vec<NodeId>,   // 目录才有；DFS 顺序
    pub size: u64,          // 子树合计（聚合后）
    pub own_size: u64,      // 直属文件字节（不含子目录）
    pub file_count: u32,    // 子树文件数
    pub dir_count: u32,     // 子树目录数
    pub mtime: i64,         // unix 秒
    pub kind: NodeKind,
    pub ext_id: u16,        // 扩展名 intern 表下标；无扩展名 = 0
    pub depth: u16,
    pub error_count: u32,   // 该目录下不可读条目数（聚合到祖先）
}

pub struct Tree {
    pub nodes: Vec<Node>,
    pub root: NodeId,
    pub root_path: PathBuf,
    pub exts: Vec<Box<str>>,          // ["", "jpg", "mp4", ...]
    pub ext_stats: Vec<ExtStat>,      // 按 ext_id 索引
    pub stats: ScanStats,
}
```

内存预算：Node 约 80B + children Vec 均摊 24B + name 均摊 ~20B ≈ 124B/节点。100 万节点 ≈ 124MB，加 jwalk 与排序临时量，峰值控制在 350MB 内。**如果 benchmark 超标**，第一个优化是把 `children: Vec<NodeId>` 换成 `first_child`/`next_sibling` 链（省 24B/节点），不改其它接口。

## 3. 扫描算法

```
1) jwalk::WalkDir (follow_links=false, sort=false, parallelism=rayon default)
   逐条产出，DFS 前序；用 (depth, NodeId) 栈确定 parent。
2) 每条 entry：
   - 符号链接 → NodeKind::Symlink，size = 0，不进入（不跟随）
   - 目录 → 新建 Dir 节点，push 到栈
   - 文件 → 若 nlink>1 且 (dev,ino) 已见 → size 记 0 并标 dup（硬链接去重）；
            否则 size = len
   - 读 metadata 失败 / 权限拒绝 → error_count 记到最近可读祖先，不中断
   - 跨文件系统（unix: st_dev != root_dev）→ 若 cross_filesystems=false，跳过该子树
3) 遍历结束后：nodes 逆序单趟聚合（前序保证子节点索引恒大于父节点）
   parent.size += child.size; parent.file_count += child.file_count + (child 是文件 ? 1 : 0)
4) topN / ext_stats 各一趟线性扫描
```

不变量（**必须有测试**）：
- `I1` 对任意目录节点：`size == own_size + Σ children.size`
- `I2` 对任意目录节点：`file_count == 直属文件数 + Σ children.file_count`
- `I3` 根节点 `size` 与 `du -sB1` 的差值 ≤ 0.5%（fixture 上）
- `I4` 所有节点 id 唯一且 `nodes[id].parent` 链最终到达 root，无环

取消：`Arc<AtomicBool>`，每 4096 条检查一次；取消后仍返回已扫部分（`stats.cancelled = true`）。

进度：扫描线程内 `AtomicU64 entries/bytes`，独立 ticker 线程每 200ms 通过 Tauri 事件推一次（不用每条都发事件）。

## 4. IPC 契约（**权威版本**）

TS 侧 `app/src/lib/types.ts` 与本表逐字一致，camelCase。

```ts
type NodeKind = 'dir' | 'file' | 'symlink'

interface NodeView {
  id: number            // NodeId
  name: string
  size: number          // 子树字节
  ownSize: number
  files: number         // 子树文件数
  dirs: number
  mtime: number         // unix 秒
  kind: NodeKind
  hasChildren: boolean
  errorCount: number
}

interface Drive { name: string; mountPoint: string; totalBytes: number; availableBytes: number }

interface ScanSummary {
  scanId: string
  rootPath: string
  root: NodeView         // id 恒为 0
  elapsedMs: number
  entries: number
  errors: number
  cancelled: boolean
}
```

| 命令 | 入参 | 返回 |
|---|---|---|
| `list_drives` | — | `Drive[]` |
| `start_scan` | `{ path, options?: { crossFilesystems?: boolean, followSymlinks?: boolean, exclude?: string[] } }` | `{ scanId: string }` |
| `cancel_scan` | `{ scanId }` | `void` |
| `list_children` | `{ scanId, nodeId, sortBy: 'size'\|'name'\|'files'\|'mtime', desc: boolean, offset: number, limit: number, minSize?: number, filter?: string }` | `{ total: number, items: NodeView[] }` |
| `get_node` | `{ scanId, nodeId }` | `NodeView` |
| `node_path` | `{ scanId, nodeId }` | `string` |
| `top_files` | `{ scanId, limit: number, minSize?: number }` | `{ id, name, path, size, mtime }[]` |
| `type_stats` | `{ scanId, topN: number }` | `{ ext: string, bytes: number, files: number }[]` |
| `save_snapshot` | `{ scanId }` | `{ path: string }` |
| `list_snapshots` | — | `{ path, rootPath, createdAt, totalBytes, entries }[]` |
| `diff_snapshots` | `{ aPath, bPath, limit: number }` | `{ grown: DiffRow[], shrunk: DiffRow[], grownBytes, shrunkBytes }`，`DiffRow = { path, sizeA, sizeB, delta }` |
| `open_path` | `{ path, reveal?: boolean }` | `void` |
| `move_to_trash` | `{ paths: string[] }` | `OpResult` |
| `delete_permanent` | `{ paths: string[], confirmText: string }` | `OpResult` |
| `platform_info` | — | `{ os: 'linux'\|'macos'\|'windows', homeDir: string }` |

```ts
interface OpResult { ok: string[]; failed: { path: string; error: string }[] }
```

事件（`listen`）：

```ts
'scan://progress'  { scanId, entries, bytes, currentPath, elapsedMs }
'scan://done'      ScanSummary
'scan://error'     { scanId, message }
```

规则：
- 所有命令命名 snake_case；JS 侧对象字段 camelCase（Tauri 自动转换 `rename_all = "camelCase"`）。
- `list_children` 中 `filter` 只做文件名子串匹配（大小写不敏感）；`minSize` 作用于 `size`。
- `desc=false` 时按升序；`sortBy` 缺省 `size` + `desc=true`。
- 单次 `limit` 上限 5000（超出截断）。

## 5. 并发与生命周期（Rust 侧）

```rust
// src-tauri/src/state.rs
struct AppState { scans: Mutex<HashMap<String, Arc<ScanHandle>>> }
struct ScanHandle { tree: RwLock<Option<Arc<Tree>>>, cancel: Arc<AtomicBool>, alive: AtomicBool }
```

- `start_scan`：立刻返回 `scanId`，`std::thread::spawn` 跑扫描；完成时写 `tree`、发 `scan://done`。
- 扫描中被删除的旧 scanId：`alive=false`，命令返回 `Err("scan not found")`。
- **只保留最近 3 个扫描结果**，更早的释放（个人自用足够，防止百万节点×N 占内存）。
- 所有 Tauri 命令用 `Result<T, String>`，错误字符串带上下文（`"读取 /proc/1: Permission denied"`）。

## 6. 安全护栏（Rust 侧，不可绕过）

```rust
// crates/disklens-core/src/guard.rs
pub fn is_protected(path: &Path, home: &Path) -> Option<&'static str>
```

拒绝清单（返回拒绝原因，UI 展示）：
- 根目录本身：`/`、任意盘符根（`C:\`）、`/System`、`/usr`、`/etc`、`/bin`、`/lib`、`/var/lib`、`/boot`
- `C:\Windows`、`C:\Program Files`、`%SystemRoot%`
- `home` 本身、`home/Projects`（代码）、`home/Documents`、Obsidian 仓库、`~/.ssh`、`~/.hermes`
- 任何规范化后（`canonicalize`）落在上述路径**之上**的目标（父目录保护）
- 路径含 `..` 或为空 → 直接拒绝

`delete_permanent` 额外要求：`confirmText` 必须等于目标 basename（防手滑）；`move_to_trash` 只需 UI 一次确认。回收站失败**绝不**降级为永久删除。

## 7. 前端结构

```
app/src/
  main.tsx  App.tsx
  i18n/zh.ts                // 全部中文文案集中
  lib/types.ts              // 契约镜像
  lib/format.ts             // formatBytes / formatMtime / formatCount（纯函数，有单测）
  lib/backend/index.ts      // export const backend: Backend = isTauri() ? tauriBackend : mockBackend
  lib/backend/tauri.ts
  lib/backend/mock.ts       // 确定性 ~20k 节点假树，含 node_modules/.cache 形态
  lib/tree.ts               // flattenRows(expanded, cache) / compare 排序（纯函数，有单测）
  store/scanStore.ts        // zustand：scanId/summary/expanded/childCache/selection/sort
  components/
    TopBar.tsx  Breadcrumb.tsx  ScanProgress.tsx
    TreeView.tsx            // TanStack Virtual + 每行占比条
    TreemapCanvas.tsx       // d3.treemap 算布局 + Canvas 画
    Sunburst.tsx            // d3.partition + d3.arc + SVG
    TypeStats.tsx  TopFilesPanel.tsx
    ContextMenu.tsx  DeleteDialog.tsx  Toast.tsx
    ui/{Button,Modal,Checkbox,Spinner}.tsx
```

状态流：
1. `startScan` → 订阅 progress/done → 存 summary。
2. 展开节点 → `list_children`（带 cache，key=`${nodeId}:${sortBy}:${desc}:${filter}`）→ 合并到 rows。
3. 点击 Treemap 扇区 → `navigateTo(nodeId)` → 同步 expanded 祖先链 + 滚动到该行。
4. 选中项设 → 底部显示合计大小 → 删除对话框。

**性能红线**：`TreeView` 只渲染可视行（overscan 8）；Treemap 只在 `(nodeId, size, viewport)` 变化时重算布局；子节点请求去抖 80ms；任何 `list_children` 结果按 scanId+nodeId 缓存，重扫时整体清空。

## 8. 快照格式

```json
{ "v": 1, "rootPath": "/home/zys", "createdAt": 1762600000, "totalBytes": 81000000000,
  "dirs": [["/home/zys/Projects", 3650723840], ...],        // size >= 1MiB 的目录
  "files": [["/home/zys/big.bin", 818000000], ...] }        // Top 20000 大文件
```
gzip 存 `~/.local/share/disklens/snapshots/<root-slug>-<ts>.json.gz`（macOS/Windows 用 Tauri `app_data_dir()`）。diff 按路径 join，只报 |delta| ≥ 1MiB 的行。
