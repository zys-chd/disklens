# 实施计划（并行开发任务书）

> 执行方式：subagent-driven。一个任务一个子代理，文件所有权互不重叠。
> 每个任务完成定义 = 自己能跑通验证命令 + 报告里贴真实输出（贴不出=没完成）。

## 并行波次

```
Wave 1（并行）: T1 核心引擎(Rust)  ‖  T3 前端(React+Mock)
Wave 2（依赖 T1）: T2 Tauri 外壳与命令层
Wave 3: T4 集成 + 验收 + 基准 + 文档
```

## T1 — Rust 核心引擎（crates/disklens-core）

**创建**：`Cargo.toml`(workspace)、`crates/disklens-core/{Cargo.toml,src/*.rs,tests/*}`、`scripts/bench.sh`

模块：
```
src/lib.rs        导出 Tree/ScanOptions/scan()/query/snapshot/guard/ops
src/model.rs      Node/Tree/NodeKind/ExtStat（见 03-架构 §2）
src/scan.rs       jwalk 遍历 + 建树 + 取消 + 进度回调
src/aggregate.rs  逆序聚合一趟（I1/I2 不变量）
src/query.rs      children(node, sortBy, desc, offset, limit, minSize, filter) / top_files / type_stats
src/snapshot.rs   保存(list_snapshots)/加载/diff
src/guard.rs      is_protected(path, home)
src/ops.rs        move_to_trash / delete_permanent（先 guard，再执行，逐项报告）
```

**必须做到**
- 硬链接去重（unix: `(st_dev, st_ino)`；windows: `file_index()`；其它平台不启用）
- 符号链接不跟随，自身 size=0
- 跨文件系统：`cross_filesystems=false` 时不进入（unix 用 `st_dev`）
- 权限/读失败不 panic，`error_count` 聚合到最近可读祖先
- 取消：`Arc<AtomicBool>`，每 4096 条检查
- 进度回调 `Fn(Progress)`，由调用方决定节流（core 里不睡不等）

**验证**（贴真实输出到报告）
```bash
cargo test -p disklens-core              # 全绿，且包含 docs/04 §2 全部夹具场景
cd crates/disklens-core && cargo run --example scan -- ~/Projects   # 与 du -sB1 对照，误差打印
/usr/bin/time -v ...                     # 峰值 RSS 记录
```

## T2 — Tauri 外壳（src-tauri/）

**创建**：`src-tauri/{Cargo.toml,build.rs,tauri.conf.json,src/main.rs,src/lib.rs,src/state.rs,src/commands/*.rs,capabilities/default.json}`；改根 `Cargo.toml` 加 member。

- 命令表严格按 03-架构 §4，`#[tauri::command(rename_all = "camelCase")]`
- 只保留最近 3 个扫描；`scanId` 无效返回明确错误
- 进度事件 200ms 节流；`scan://done` 带 ScanSummary
- 删除类命令先过 `guard::is_protected`
- 验证：`cargo build -p disklens`（或 `cargo check`）；`cargo tauri dev` 能起窗口（无 DISPLAY 时至少 `cargo check` 通过并说明）

## T3 — 前端（app/）

**创建**：`app/**`（Vite + React 19 + TS + Tailwind 4 + zustand + d3-hierarchy/d3-shape + @tanstack/react-virtual + vitest）

- `lib/types.ts` 与契约逐字一致；`lib/backend/index.ts` 按 `isTauri()` 选实现
- `mock.ts`：确定性假树 ~20k 节点（`size` 呈幂律分布，含 node_modules/.cache 形态），支持分页/排序/过滤/删除模拟
- 组件清单见 03-架构 §7
- 视觉：深/浅色跟随系统；强调色 `#6366f1`；语义色 safe `#22c55e` / warn `#f59e0b` / danger `#ef4444`；行高 28px、等宽数字（`tabular-nums`）；不用第三方 UI 库
- 验证：`cd app && npm ci && npm run build && npx vitest run`（贴输出），并在 mock 模式下 `npm run dev` 能起

## T4 — 集成（主控 + 一个子代理）

`app/dist` 联调、`cargo tauri build`（Linux 制品）、mock 截图验收、写 `docs/bench.md` 与 README、跑 docs/04 §5 清单。

## 完成定义（每个任务都要满足）

1. 验证命令的真实输出贴在报告里（不许写"应该通过"）。
2. 没有超出自己所有权目录的文件改动。
3. 未实现/走捷径的地方显式写 `shortcut: <限制>, <何时升级>` 注释并在报告里列出。
4. 报告分三块：做了什么 / 验证证据 / 已知缺口。
