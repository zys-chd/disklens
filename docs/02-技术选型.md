# 技术选型

> v1.0 ｜ 2026-11-09 ｜ 决策已定，不再逐项讨论

## 1. 外壳/UI 栈对比

| 方案 | 扫描性能 | 包体 | UI 表现力 | 跨平台成本 | 结论 |
|---|---|---|---|---|---|
| **Rust 核心 + Tauri 2 + React** | ★★★★★ | ~10MB | ★★★★★ | 低（系统 WebView） | **采用** |
| Electron + Node | ★★☆ | ~120MB | ★★★★★ | 低 | 包体/内存太大，扫描慢 |
| PySide6（既有版） | ★★☆（GIL + scandir） | ~120MB | ★★★☆ | 中 | 已有 v0.3，性能天花板低，UI 现代感有限 |
| Go + Wails | ★★★★ | ~15MB | ★★★★ | 低 | 可行；Rust 在并行 I/O + 紧凑内存模型上更优，且生态（trash/jwalk）成熟 |
| 原生（Qt/C++ / SwiftUI+WinUI） | ★★★★★ | 小 | ★★★★★ | **高**（三套代码） | 个人自用不值得 |

选 Tauri 的**真实理由**：扫描热点在 Rust（无 GC、`jwalk`+`rayon` 可压满 NVMe 队列），而 UI 复杂交互（树/Treemap/旭日/虚拟滚动）用 Web 技术开发效率最高。WebView 用的是系统自带（WebView2 / WKWebView / WebKitGTK），所以包体小、内存可控。

## 2. Rust 依赖

| crate | 用途 | 备注 |
|---|---|---|
| `jwalk` 0.9 | 并行目录遍历 | DFS 前序遍历顺序稳定，可边扫边建树；内置 rayon 并行 |
| `rayon` | 并行/聚合 | jwalk 已依赖，直接用 |
| `serde` + `serde_json` | IPC 数据结构、快照 | |
| `flate2` | 快照 gzip | 快照压缩后体积降 5-8 倍 |
| `trash` 5 | 跨平台移到回收站 | Win: SHFileOperation / macOS: NSFileManager / Linux: gio（freedesktop trash 规范） |
| `openssl`/`rustls` | — | **不需要**（无网络功能） |
| `thiserror` | 错误类型 | 只用于 core → `AppError` 序列化回前端 |
| `open` 5 | 用默认程序打开文件/目录 | 三平台一致封装 |
| `dirs` 6 | home / 盘符探测 | |
| `sysinfo` 0.33 | 挂载盘列表 + 容量 | 或 `sysinfo::Disks`（跨平台） |

**明确不用**：SQLite（快照用 gzip JSON 足够）、tokio 异步扫描（IO 密集用阻塞线程池更简单，Tauri 命令里 `spawn_blocking`）。

## 4. 打包

- Linux：`.deb` + `.AppImage`（tauri bundler 内置）
- Windows：`.msi`（WiX）+ `.exe`（NSIS）
- macOS：`.app` + `.dmg`（无签名，本机自用需 `xattr -dr com.apple.quarantine`）
- 交叉构建：Linux 上仅构建 Linux 制品；Windows/macOS 由 GitHub Actions 矩阵构建（本次只提供 workflow 文件，不跑）

## 5. 关键取舍记录

1. **树不整棵过 IPC**：Rust 持有 arena，前端按「父节点 + 排序 + 分页」拉子节点。100 万节点整树 JSON ≈ 200MB+，必然卡死。
2. **Treemap 用 Canvas 而非 SVG**：5000+ 矩形 SVG 会产生 5000 个 DOM 节点，滚动/重绘掉帧。
3. **删除只走 `trash` crate**：不自己拼 `gio trash` 命令，避免三平台分支。
4. **永久删除即使确认也走"先算大小→再执行→逐项报告"**，不引入 dry-run 模式开关（多一个模式=多一倍测试）。
